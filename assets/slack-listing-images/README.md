# Slack Marketplace listing images

Three 1600×1000 PNGs for the Bratrax listing. Each one is a **real Slack
screenshot** on a Bratrax-branded plate — only the identity is edited.

| File | Headline | Shows |
|---|---|---|
| `01-revenue-chart.png` | See what actually drove **revenue** | A charted answer with the full button row — deep link plus the 7/30/90-day re-runs |
| `02-follow-up.png` | Ask the obvious **follow-up** | Two exchanges in one thread, the second scoped off the first |
| `03-suggested-prompts.png` | Know what to ask on **day one** | The Messages tab on first open, with the three suggested prompts |

Upload `01` first — Slack's reviewers study the first image hardest, and it is
the one that shows the most functionality in a single frame.

## Why real captures, not rebuilt ones

The first attempt redrew the Slack cards in HTML, following Slack's own example
listing image (their Helpdesk card is a redraw, not a capture, deliberately
zoomed so it survives the gallery thumbnail). That was the wrong call here. A
reconstruction that is 95% right — slightly wrong button radius, slightly wrong
badge weight — reads as suspicious to a reviewer holding the listing next to the
live app. A real capture cannot. Legibility is the price, and it is worth
paying.

## Regenerating

```bash
python3 patch.py     # originals/ -> shots/ : photo -> initial tile, name -> "Julia"
python3 make.py      # shots/ + branded plate -> the three 1600x1000 PNGs
```

Needs Pillow and a Chromium build; the Chromium path is a constant at the top
of `make.py`.

- `originals/` — the untouched captures. Never edit these.
- `shots/` — generated by `patch.py`. Never edit by hand; they are overwritten.
- `fonts/` — Lato, vendored because the patch has to match Slack's own UI face.

Headlines live in the `IMAGES` list in `make.py`; the plate styling is the
`PLATE` template in the same file.

## What `patch.py` changes, and what it deliberately does not

Only identity: the profile photo becomes a plain initial tile, and
"Yuliya from Bratrax" becomes "Julia". Every number, timestamp, button and
pixel of Slack chrome is the original capture.

Two details make the name swap invisible rather than obviously pasted:

- **Real Lato.** Slack's UI face is Lato, so the replacement is drawn in it
  rather than a lookalike.
- **The point size is solved, not guessed.** The three captures were taken at
  different UI scales (16px, 20px, 20px). `patch.py` re-renders the *original*
  string and binary-searches the size until its width matches the pixels being
  replaced.

"Julia" is far shorter than "Yuliya from Bratrax", so the adjacent timestamp is
erased and redrawn too. Leaving it in place would open a gap that never occurs
in Slack — exactly the kind of tell that reads as doctored.

The avatar threshold is 235, not something closer to white: the photo's rounded
corners are antialiased, and a looser threshold swallows that halo into the
bounding box and oversizes the replacement tile.

## Known trade-off on image 01

That capture is 1100×800 — taller than the required 8:5 — so it can only scale
to 962px wide inside the frame and its text is the smallest of the three. Its
content bounds are already tight (1062×767), so cropping buys nothing.

If it ever needs to be more legible, retake the thread in a **wider, shorter**
browser window: the answer text reflows to fewer lines, the thread gets wider
and shorter, and it fills the 8:5 frame at a larger scale. Drop the new capture
in as `originals/raw-chart.png` and re-run both scripts — the header hints in
`patch.py` will need re-measuring against the new UI scale.

## The render trap

Headless Chromium's `--window-size=W,H` sizes the *window*: the page gets a
viewport 87px shorter while the screenshot is still H tall, padded out with the
body background. The graph paper and vignette are `position: fixed`, so they
cover only the viewport and leave a band with no grid across the bottom.
`make.py` compensates the window height so the viewport lands at exactly 1000,
then crops back with Pillow. If Chromium is upgraded, re-measure that offset —
the script fails loudly rather than silently shipping a seam.
